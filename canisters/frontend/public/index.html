03 / Principles

Small surface. Clear contract.

Event Horizon adds a prompt signal path without taking ownership of application correctness.

01

Fast path

Canonical ICP is read through its legacy block log; compatible non-ICP ledgers are read through ICRC-3. A global trigger attempts one poke([]) when a poll processes any block.

02

Correctness stays yours

Your canister keeps its own authoritative ledger cursor and a slower independent reconciliation timer. An Index is optional application infrastructure.

03

ICP-funded

A patron productively endows an exact route through Jupiter Faucet. Event Horizon admits it permanently only after a qualifying Faucet payout and complete Historian evidence; recurring payouts, not endowed principal, fund pooled operating cycles.

04

Specific hints win

A non-empty poke reports each retained specific target and its maximum observed qualifying transfer amount; an empty poke reports global-only activity. Both are best-effort hints, and max_amount is not proof of payment. There are no acknowledgements, retries, or delivery guarantees.

Open Source & Verifiable

Event Horizon’s implementation is public and designed for independent verification. Reproduce the production Wasm from a reviewed source revision, then compare its SHA-256 with the module hash installed on the canister.

Also check the canister identity, instance configuration and current controllers. A matching build or the frontend’s reviewed backend-hash registry does not independently establish live controller status.

Designed for Immutability

The backend has immutable instance configuration and no administrative control API. It is designed for eventual finalisation through controller removal after operational acceptance; this is an intended step, not a claim that controllers have already been removed.

Once controller removal is complete, the backend cannot ordinarily be upgraded or reconfigured. The frontend remains separately controlled and can continue to evolve.

Productive Endowment Funding

Patrons can fund subscription declarations through Jupiter Faucet. ICP principal stays in Jupiter’s productive staking path; recurring maturity-derived ICP payouts can eventually reach Event Horizon, which converts retained payouts into pooled operating cycles rather than assigning cycles to individual subscribers.

Endowing principal does not immediately admit a subscription: admission requires a qualifying Faucet payout and Historian evidence. Ongoing operation depends on realised receipts and costs. Perpetual service is an objective, not a guarantee.

Powered by Internet Computer Protocol

The Internet Computer hosts Event Horizon’s backend canister and certified frontend assets. Ledger queries identify relevant activity, canister-to-canister notifications provide best-effort wake-up hints, and cycles converted from ICP pay for operation.

Independent instances can observe compatible non-ICP ledgers, while subscription funding and cycles conversion remain ICP-based. Subscribers still reconcile authoritative Ledger data; notifications are not a delivery guarantee.

Open deployment

Additional immutable instances.

Event Horizon’s backend is ledger-generic. Additional immutable instances can be deployed by anyone for compatible ICRC token ledgers. Before final deployment, arrange a dedicated Jupiter Faucet alias through its community review process.
