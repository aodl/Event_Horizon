# Fully on-chain subnet widget validation

Validation date: 2026-11-13. Frontend presentation change; no deployment.

## Design and boundaries

The local decorative network thumbnail is fixed at the lower-left, normally
232×140 CSS pixels and 192×108 on narrow or short screens. Safe areas adjust
its inset. The launcher stays visible and keyboard reachable while page
controls have focus; its separate Close action clears the overlay.
A native dialog uses 90vw × 88dvh with 90rem × 62rem caps, and nearly the full
viewport on phones and short screens. Parent controls remain available
when enlarged text requires internal scrolling. No widget animation is added.

The small initializer owns collapsed, expanded and dismissed states, a single
iframe, native dialog listeners, focus and scroll restoration, and disposal.
Escape received by the parent minimises. Cross-origin Escape interception is
not guaranteed. Dismissal is terminal until reload and uses no browser storage.
An initial conventional link supports missing JavaScript or native dialog.

A continuously running map inside the thumbnail is intentionally avoided:
initial loading uses only local SVG, and assigns no iframe URL. Explicit
expansion loads the approved external application; minimisation, dismissal,
pagehide and disposal remove the URL. No Event Horizon backend requests,
network discovery, proxying, message protocol or dependency was added.
The dashboard is trusted for display independently of certified parent assets;
subnet composition proves neither controller removal nor source provenance.

## CSP

Only the page policy gains
`frame-src 'self' https://dashboard.internetcomputer.org`. Explicit `'self'`
is necessary: an actual Chromium regression caught that dashboard-only
`frame-src` blocks the existing same-origin SVG object browsing context.
All previous directives and the separate SVG policy remain unchanged,
including `frame-ancestors 'none'`, the self-only scripts/styles and the
`https://icp-api.io` parent connection allowlist.

## Validation results

Canonical security and reproducibility gates run after the implementation is
committed and the working tree is clean. Their results are recorded in the
completion receipt and retained logs; no deployment is part of validation.

`cargo test --locked --workspace` passed: 146 tests passed, zero failed;
129 intentionally ignored integration tests were outside that unit run.
The two relevant frontend integration tests passed separately (2 passed,
zero failed). They verify actual canister responses, certificate headers,
static bytes, routing/cache behaviour, SVG embedding and the resulting page
CSP, including the unchanged protections and the approved frame source.
The first cold-build attempt lost its local PocketIC server while compiling;
the two frontend tests now prepare Wasm **before** starting the replica. The
rerun passed with that ordering. This changes test setup only.

`cargo clippy --locked --workspace --all-targets -- -D warnings` passed;
`cargo fmt --all -- --check` and `python3 tools/static-check.py` passed.

Frontend build and all 145 Node tests passed, including seven new focused
widget tests. Browser state, focus, keyboard iframe entry/exit, parent Escape,
rapid actions, dismissal, reload and scroll-restoration checks passed.

`node tools/scripts/validate-subnet-widget.mjs --live --no-screenshots` passed
for the map integration. A final `--no-screenshots` run passed again after
tightening dismissal focus to the existing fixed skip link, which becomes
visible without scrolling even when the main landmark is off-screen.
The launcher remains visible and in normal Tab order while page content has
focus; a sequential footer → launcher Tab/Shift+Tab regression guards this. A preliminary canonical attempt was
cancelled before artifact completion when this keyboard issue was found; the
corrected implementation is the candidate for canonical validation.
All eight requested viewport sizes passed, plus 200% text,
reduced motion and forced colours. The enlarged-text check scrolls to the source
links and then rechecks that **both** controls remain in the viewport. A final
screenshot is `observations/subnet-widget/browser/text-200-percent-final.png`.
The first viewport run also retained collapsed/expanded screenshots at all eight
sizes and real dashboard screenshots on desktop and emulated touch mobile.
The later run kept all assertions and skipped repeated screenshot capture
because this shared host intermittently timed out during Chromium SVG capture.

Live tests loaded the genuine map's data with no console errors, exercised a
country filter until data-centre details appeared, then successfully minimised,
reopened and dismissed the map. The sandbox required no extra capabilities.
`node tools/scripts/validate-ledger-counter.mjs --no-screenshots` also passed:
hero artwork lifecycle/reduced motion, compact-heading geometry, four fact
links and ordering, count/rate alignment, exact accessible sample, operating
status, instance switching, pricing/memo isolation, fragment history, and text
reflow. Screenshot capture remains enabled by default; the optional flag skips
capture only, preserving all browser assertions. This run used a longer default
browser timeout for this contended environment and corrected two stale fact
labels to match existing product copy.

An isolated initializer test with the dashboard deliberately unreachable
confirmed usable controls, visible external links, iframe unloading, no eager
external request and no Event Horizon backend request. Evidence is in
`observations/subnet-widget/browser/evidence.json`; the separately retained
real-map run is `live-final-evidence.json` in the same directory.

The preliminary security wrapper completed `cargo audit` with six existing
warnings, then failed at `cargo deny` on `pin-utils` 0.1.0, an unmaintained
PocketIC tooling dependency (`RUSTSEC-2026-0441`). The unchanged lock also
received the informational rustix xattr warning (`RUSTSEC-2026-0486`). No
new dependency, exception or audit-policy change is introduced. The wrapper's
later npm/OSV steps were run independently: `npm audit --omit=dev` passed with
zero vulnerabilities; OSV reported the same existing `pin-utils` and `rustix`
advisories (two unknown-severity findings). The wrapper will be rerun after the
implementation commit as required.

## Known limits

No mainnet deployment or backend upgrade is authorised or performed. The current
published Event Horizon origin cannot demonstrate an undeployed CSP; repeat the
smoke after a separately reviewed frontend upgrade. Browser emulation cannot
replace physical iOS Safari/VoiceOver and Android device review. Cross-origin
failures cannot all be detected; the parent always retains controls and external
links. Sandbox popups and top navigation remain intentionally unavailable;
visitors can use the parent links for the full dashboard.

Browser evidence, headers, certificate observations and logs are retained under
ignored `observations/subnet-widget/`. Browser launch used existing libraries
from `/home/codexdev/.cache/browser-libs/root/usr/lib/x86_64-linux-gnu` via
`LD_LIBRARY_PATH`; no system installation or privilege escalation was used.
