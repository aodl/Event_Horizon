# Protocol and floating subnet refinement validation

The reviewed base is `e49a907668a5de83bed45250f29c400610e8a8ac`. This report
covers implementation validation. Exact source/merge identities, canonical Wasm
hashes, CI links and deployment results belong to the separately retained release
receipt, `observations/floating-subnet/release-receipt.json`, and the final release
report; this document alone is not evidence of a mainnet upgrade.

## Implementation

Exactly six native grouped disclosures remain, ordered **The protocol → 01 / Choose
→ 02 / Compose → 03 / Complete → Design → Open deployment**. They start closed
without a relevant fragment and permit zero or one open. The four original
explanations are ordinary `h3` subsections inside The protocol. Their IDs, focus
targets, icons, links and complete paragraphs remain. Paragraph, icon and link
attributes were compared byte-for-byte with the reviewed base; all four Design
principle articles also remain byte-identical. Hero and footer are preserved.

The dark summary hover fill is removed; keyboard outlines and chevrons remain.
CSS progressively enhances native state with 300ms ease-in-out intrinsic sizing
where supported. The existing body wrapper fades for 280ms on entry; engines
without intrinsic interpolation use clean instantaneous native collapse. An
attempt to retain a descendant closing fade in WebKit left a pending animation
and delayed blank space, so it was rejected. The conservative fallback avoids
engine detection, height caps, cloned content and a custom animation controller.
Reduced motion disables content and chevron transitions. Fragment correction is
finite and cancellable, respects later keyboard focus, and uses the CSS duration
only when height animation requires it. No expansion-state store is added.

The fixed bottom-left widget uses one iframe at **600×520 / .25 = 150×130** in
compact mode. Its inert, aria-hidden preview has disabled pointer/focus entry;
Expand and Dismiss are separate controls. Initial non-modal opening uses the native
`open` property to preserve the first Tab destination; later mode switching uses
native dialog methods. A preview wrapper keeps their hit areas
separate when enlarged text grows the toolbar. Expansion closes and reopens the
same mounted dialog modally; minimisation restores its non-modal presentation.
Parent Escape minimises. Dismiss releases the frame document until reload.
Direct `#subnet-map` navigation opens the modal unless dismissed. Focus restores
sensibly even when history navigation has hidden the original control.

One ResizeObserver adapts the existing expanded calculation: W ≤ 760 uses native
W×520; W > 760 uses 760×520 scaled uniformly by W/760 and reserves the complete
transformed height. The modal scrolls with a sticky toolbar and safe-area insets.
There is no polling, scroll listener, second geometry controller or iframe clone.
Loading starts in a task after application bootstrap. The unscaled dark layer
clears 500ms after document load; a 12-second deadline retains a dark pending
surface and exposes the permanent fallback. These milestones do not establish
external data readiness. No-JavaScript visitors retain a conventional link.

The approved URL, sandbox, no-referrer policy, page/SVG CSP, Candid, backend
registry, deployment mappings and backend implementation are unchanged. External
Dashboard assets/data and popup destinations remain outside Event Horizon's
certification. Live links must sever the opener; popup permission alone does not
enforce that policy for arbitrary future Dashboard code.

## Validation and limits

- Frontend setup/build: passed; bundle generated by esbuild, never edited by hand.
- Frontend unit suite: **154 passed**. Rust workspace: **146 passed**.
- Managed PocketIC: **129 passed, zero failed**. Both certified-frontend scenarios
  were replayed after the final markup and asset changes.
- Strict formatting, locked Clippy with warnings denied, static checks and the
  security scan passed under the unchanged audit policy.
- Chromium 153.0.8010.12, Firefox 155.0 and WebKit/WPE 26.6 were exercised with the
  maintained harness in an isolated Playwright 1.63.0 container. Earlier local
  Chromium 149 / Firefox 151 checks also covered lifecycle and real Dashboard use.
  Root package/dependency pins were not changed for this testing environment.
- Each engine exercised 1920×1080, 1440×900, 1024×768, 768×1024, 390×844,
  375×667, 320×568 and 844×390. Native keyboard exclusivity, rapid switching,
  nested/repeated/history fragments, hidden-content traversal, modal background
  inertness, focus restoration, reduced motion, forced colours and 200% text were
  checked. Deterministic service/iframe fixtures are separate from genuine live
  Dashboard checks. Intentional service failures use CORS-valid HTTP responses.
- One frame node and one external document request survive repeated expansion,
  minimisation and resizing. The Dashboard emits additional same-document history
  events; these are not reloads. Live country state, geographic interaction,
  keyboard/touch links, null opener, functional destination pagination and unchanged
  parent URL were checked. No Event Horizon backend query was added by the widget.
- Genuine Chromium browser zoom at 100/125/150/175/200% and back preserved geometry,
  accessible controls and one document request. Actual back/forward-cache restoration
  preserved both compact and expanded modes, the page token and the frame document.
- Seven requested settled screenshots were captured and inspected. Hero/ledger,
  operating status, instance/configuration verification, pricing, memo construction,
  delayed preview and form-state regressions pass the ledger/hero browser harness.

The live preview runs the complete external application. Observations under shared
host load showed roughly 170–180 initial Dashboard-origin requests and about
0.9–1.6 MB of Dashboard-origin response bodies across the live path, in addition to
parent assets and IC API traffic. Country controls appeared in roughly 9–45 seconds
in these runs; this is not a controlled performance benchmark. Scaling does not
reduce that workload. Repeated mode changes added no document request; dismissal
releases the application. Parent response-load status cannot prove later external
paints or registry-data completion.

Physical Safari, physical devices and manual screen-reader testing were unavailable.
WebKit automation is not Safari testing. Firefox/WebKit intentionally retain native
instantaneous collapse. Wide proportional scaling can offset part of browser
magnification; the permanent external link offers independent native zoom. External
network failures and coarse headless paint timing are not worked around in production.

## Scope and complexity

The widget controller is 72 lines; the extracted loader is 34 lines. Native HTML
owns disclosure and modal state. Five widget listeners, one frame-load listener, one layout observer, the
bootstrap task, two loading timers and finite fragment positioning have explicit
purposes and disposal. No production dependency, framework, persistent preference,
backend query, dashboard DOM manipulation or general router is introduced. The
minified bundle grows by approximately 1.8 KB.
